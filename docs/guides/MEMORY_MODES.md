# 记忆模式与个人配置

需要 Node.js >=22.13，建议 Node.js 24（仓库包含 `.nvmrc`）。

## 选择记忆模式

控制台左侧「记忆管理」提供两种整理策略，默认保持轻量模式。**两种模式都长期保存记忆**，不再按天数或条数自动淘汰；模式选择影响整理与检索方式，不决定是否长期保存。

| 模式 | 存储 | 行为 |
| --- | --- | --- |
| 轻量 | `state/social-v2.json`、共用 SQLite 原文归档、经历与通话文件 | 直接记录话题、想法、印象；已过期想法保留，只在提示词中筛除；共享经历及电话文字长期保存 |
| 长期 | `state/long-term-memory.sqlite` | 按角色和会话分别存档案、事件、待完成事项及新增聊天原文；电话文字仍使用原存储 |

切换不清空原有数据。两种策略均用于当前二代记忆系统；智能整理需要先选择角色。人物、会话与隐私权限边界保持独立。轻量模式不再删除旧话题、过期想法、较早人物或旧印象特质；注入提示词时只选最近相关部分。共同经历长期保存，默认只向模型提供少量近期或匹配记录；通话关键词查询可遍历全部存档。

电话容器通过原有私有策略通道按来电者读取角色补充与长期记忆，不需要扩大文件挂载权限。

旧轻量记忆未记录角色归属，因此不会自动猜测迁移。选择好友或群（列表中没有时可选择对象类型并输入号码），点击「复制本会话轻量记忆」，确认当前角色合适后复制。复制包含仍存在的最近聊天、人物印象、话题和想法（包括已过期但仍保留的记录）；原文件不改动，同一角色与会话仅复制一次。共享经历和旧电话文件原样保留。已经被滚动窗口删除的消息不能恢复。

复制的旧消息用于检索追溯，不自动批量调用模型重新提炼；自动整理从之后的新消息开始，避免切换时集中消耗额度。

## 长期记忆如何工作

- 两种模式的新消息都在最近消息窗口裁剪前归档，单条文字最多 12000 字符，成功的语音转写也写入归档；不存图片二进制、网关文件地址或会话令牌。归档从本次更新后开始；未选择角色时单独保存为未绑定角色的原文，不猜测它属于后续选择的角色。
- 回复时带入少量核心档案、相关事件、当前事项和匹配原文，提示长度有预算。当前使用本地中文二字组合与英文关键词检索，不需要 embedding 服务。
- 智能整理模式默认累计 40 条消息（约 20 轮）后尝试整理；安静十分钟后也会整理不足一批的消息。全桥接同时只运行一个整理任务。
- 整理复用配置的聊天模型，但创建独立 `qq-memory` 会话；该预设从工具清单中隐藏所有工具，并在执行期拒绝工具调用。结果不会发送到 QQ。
- 整理结果必须关联本批真实用户消息与匹配原文片段；不接受助手自述作为人物事实证据。证据校验降低误记风险，但不保证模型理解完全正确，仍可在控制台纠正。
- 同类档案和同名事件原位更新，事件可从 active 更新为 resolved；保留旧版本供导出追溯。明确记忆也可使用已有 `qq_memory_*` 工具即时保存。
- 提取失败保留原文与未处理水位；控制台显示失败原因，可点击「立即整理」重试。记忆被修改、删除或切换模式后，旧在途结果不会覆盖新数据。

升级已有安装时运行 `node scripts/setup-dsh.mjs`（使用原来的 DSH_HOME/profile），重启 DSH 加载新预设。未加载前，长期归档和手动记忆仍可使用，后台整理会明确提示尚未就绪。

## 删除、导出与备份

控制台可编辑、删除和导出当前角色、当前会话的长期记忆。为避免旧原文重建已删除事实，删除操作会清理该角色和会话的原文归档，并取消旧整理结果；其他已保存记忆保留。QQ 撤回通知也会清理对应长期原文及有来源关联的提炼记忆。

删除当前模式的档案不会清空另一模式已保存的档案；纠正或删除记忆会清理本会话共用原文，防止重新提取已遗忘事实。清空整个会话还会清理当前角色在该会话的经历与通话文字。备份、导出的文件和 DSH 自身的历史会话属于独立副本，不承诺从这些副本抹除。停止桥接后备份整个 `state/`、`config.json` 和 `config.personal.json`；SQLite 在运行时可能存在 `-wal`，不要只复制正在运行的主数据库文件。升级前保留备份，避免降级写入更新版本的数据库。

## 人格与账号分离

公开 `roles/示例伙伴.md` 只包含人格，不绑定账号、职业、专属称呼或操作权限。真实 QQ、授权、音色、密钥及引用图片属于本地数据，均不提交 GitHub。

- `config.json`：聊天白名单、管理员、语音/生图服务和实际工具权限。
- `config.personal.json`：额外受保护账号、按角色和会话绑定的关系补充。该文件已被 Git 忽略；可从 `config.personal.example.json` 创建。
- 管理员账号默认不进入共享经历且不能被删除；`privacy.protectedQQs` 可以再指定其他受保护账号。

例如本地个人配置可以写成：

```json
{
  "version": 1,
  "privacy": { "protectedQQs": ["123"] },
  "rolePolicies": {
    "示例伙伴": {
      "prompt": "各会话关系分别判断，不向其他人转述私聊内容。",
      "sessionPrompts": {
        "private:123": "当前私聊的专属称呼为小林，关系以双方实际约定为准。"
      }
    }
  }
}
```

示例号码不是实际账号。`prompt` 是该角色通用规则；`sessionPrompts` 仅进入对应会话。人格和补充提示词不会授予实际工具权限。个人文件损坏会明确停止加载，避免静默失去保护。修改后重启桥接。
